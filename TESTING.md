# Validation contract

`verify.ps1` runs moon fmt/info/check, explicit JS and Wasm-GC tests, the example, a rebuilt browser engine, browser/legacy CLI/AWK CLI/session-bridge checks, saved GoAWK core, record, host and redirected IO CSV and Unicode regex vectors, pull/command bridge host contracts and generated-test checks, historical GNU Awk vectors, bounded robustness and the documented-example benchmark. Generated API and engine must correspond to the checked source.

## 0.9 current evidence

- 140 public API test groups per JS and Wasm-GC target: expressions/control flow, arrays/fields, regex matching and substitution, Unicode positions, formatting and rounding, functions and scope, nonlocal transfer, sessions/independent state, step limits, numeric coercion/NaN/hexadecimal rounding and errors.
- `tools/test-reference.mjs`: 514 independently authored cases from an unmodified official GoAWK v1.32.0 executable with `-c -N raw`. Checks exact output and exit status, except unordered array iteration is sorted; designated invalid programs compare rejection, not identical diagnostics or partial output.
- `tools/test-host-reference.mjs`: 65 real CLI cases with multiple files/program files, -F/-v and positional assignments, ENVIRON/ARGV, nextfile/exit, CRLF/Unicode, failures and output before failures, and 4.8 MB input/output. Large output compares length and SHA-256. Live runs compare native process exit statuses; cross-platform golden replay compares low eight bits, while same-platform replay also compares the native status. Fixture files are created independently in an owned temporary directory.
- `tools/test-record-reference.mjs`: 303 independently authored programs covering RS modes, RT/CRLF/paragraphs, dynamic RS, Unicode whitespace and getline in BEGIN/rules/functions/END, targets, EOF, side effects, special variables and rejection. Native output is saved separately and replayed exactly. `generate-record-tests.mjs` reproduces 19 backend groups from those native vectors; `--check` compares semantic tokens while allowing only formatter whitespace/trailing commas.
- `tools/test-io-reference.mjs`: 80 independently authored real file/pipe/process cases. It compares exact stdout, low-eight-bit exit status, presence of stderr, and every changed file's bytes/hash; diagnostic wording is not compared. Includes first-open reuse, truncate/append, close/reopen, RS/RT, target side effects, special variables, stdin/aliases, unknown streams, missing files/commands/shell, invalid syntax, buffered visibility, broken pipes, process exit codes and up to 1.8 MB pipe output. Both implementations use the same `sh` on PATH; executable SHA/version are recorded, and four missing-shell cases deliberately clear PATH. On Windows prepend the installed Git/bin directory to the current process PATH.
- `generate-io-tests.mjs` replays the first 40 saved native file programs through an in-memory IO provider in 5 backend groups. Two further groups exercise capability refusal, stream-budget cleanup and read-failure contracts. These overlap the native cases; subprocess behavior is checked on the real Node host, not the virtual provider.
- `tools/test-csv-reference.mjs`: 273 independently authored real CLI programs. 270 agree with pinned native GoAWK; three BOM/raw-token differences are separately checked against explicit current expectations and are not counted as matches. Valid programs compare exact stdout, exit status, presence of stderr and changed file contents; designated invalid programs compare rejection, not exact diagnostics/partial output. Covers CSV/TSV quotes, multiline/CRLF/EOF, comments, Unicode, modes/options, headers/names/FIELDS, split, field types/rebuilding, getline targets/files/pipes, multiple files and large input.
- `generate-csv-tests.mjs` reproduces 251 non-host/non-difference native programs in 16 backend groups. Four `csv_test.mbt` groups check 1/2/3/7/64-character provider chunks, quote/CRLF/Unicode carry, independent manual modes and per-file headers, failed reads without partial record publication, field and expanded output budgets. The generated cases overlap native coverage.
- Four `input_test.mbt` groups cover split points (1/2/3/7/16/32768 characters), shared ownership, errors, source limits and sink failures. `test-pull-host.mjs` checks 10 host contracts including a real interactive prompt and a 1.8 MB slow output consumer. The CLI matrix additionally exercises 4.8 MB BEGIN/getline output, 3.6 MB custom-separated input, cross-file getline, target scope, EOF resume and UTF-8 carry at 64 KiB.
- `tools/test-bridge-host.mjs`: four real-host checks cover invalid UTF-8 carry at the 64 KiB boundary without oversized callbacks, a command prompt followed by blocking main stdin, 1.8 MB command output with a slow consumer, and a missing worker module in an owned temporary installation. A shared permanent failure flag prevents startup failure from leaving the main thread waiting indefinitely. These are explicit host contracts, not additional native language comparisons.
- `tools/test-session.mjs`: verifies soft output batch boundaries, actual processed counts, output before batch/BEGIN failures, nextfile/exit, session cleanup and maximum simultaneous sessions. `test-awk-cli.mjs` keeps six basic CLI scenarios; original browser/combined-input CLI tests remain active.
- Live reports `evidence/awk-reference-validation.json`, `awk-record-validation.json` `awk-host-validation.json` `awk-io-validation.json` and `awk-csv-validation.json` record executable version/SHA-256, engine, CLI and source hashes. Independent requests/reference outputs are in the corresponding vectors files. `--golden` strictly checks that saved request definitions still match; replay results use separate ignored files and do not overwrite live evidence.
- Reference: official [GoAWK v1.32.0 Windows asset](https://github.com/benhoyt/goawk/releases/tag/v1.32.0). The downloaded ZIP was checked against GitHub's asset digest (SHA-256 `2cebd8d64a8eaf84b2787edec8c0274760166e077bc2bdbb69d41537b56cf32c`). The external reference binary is used only by the test harness; it is not shipped or invoked by production code.
- Historical GNU Awk 5.3.2 vectors now match 45/46 cases: default numeric formatting is fixed; its compile-time rejection of dead constant division differs from GoAWK and this interpreter. The generator `tools/reference-gawk.py` is retained. This run replays that older corpus; it does not claim a fresh GNU reference generation.
- 307 seeded bounded malformed inputs, with a 20-second worker deadline; no uncaught runtime failures. This is bounded fuzz smoke coverage, not complete robustness proof.
- Historical `tools/benchmark-csv.mjs` measured nine CLI workloads with five serial fresh processes per variant, rotating order. Four existing workloads compare with fixed 0.6.1 commit `bfe6c42`; five new workloads cover CSV numeric aggregation, multiline fields, named headers, output and TSV conversion. Every trial compares exact output/hash against native GoAWK. Timings include startup and IO, not isolated interpreter throughput or complete performance parity. Earlier benchmark tools/reports remain historical evidence.
- Benchmark: five warmups and 30 documented-example executions, runtime/CPU/median/p95 recorded locally. It is not an upstream performance comparison.

The 1235 GoAWK comparisons (1232 matches and three explicit BOM differences) are authored representative cases, not the entire upstream suite or a proof of POSIX/GoAWK conformance. Numeric/regex resource bounds, BOM and Unicode/byte/locale gaps are documented in README. Native MoonBit backend, full upstream performance and remote CI remain unverified. All work is local; no coverage upload, publication or remote execution was performed. The 0.9 local archive is separate from historical project collections.

The GoAWK 1.32 scanner and VM source were consulted for observed version-specific behavior: [input handling](https://github.com/benhoyt/goawk/blob/v1.32.0/interp/io.go), [getline instructions](https://github.com/benhoyt/goawk/blob/v1.32.0/interp/vm.go). Production code remains an independent MoonBit implementation. The scanner's chunk-sensitive cases and its non-POSIX field-target behavior are explicitly documented; passing these authored cases is not complete conformance.

## Unicode regex evidence

- `generate-regex-unicode.py --check` verifies the 199 lookup names, 2878 simple-fold links and source SHA-256 from vendored Go 1.26.3 Unicode 15.0.0 tables. The generator converts stride tables to sorted intervals and shares alias data. BSD license and provenance are retained. No Go runtime is required.
- `generate-regex-cases.py --check` selects boundaries and neighbors of every reachable property interval, aliases and all fold links, including reverse links and neighboring non-equivalent characters. The tested expected outputs are obtained independently from the official native GoAWK executable, not calculated by the generator.
- `test-regex-reference.mjs` compares 417 programs: 276408 property predicates, 8634 fold pairs, 48 match/substitution programs, 39 invalid programs and 12 FS/RS/split programs. Successful output and exit status are exact; invalid inputs compare rejection only. The native side must positively match every generated equivalence link. These are finite scalar-value boundaries, not arbitrary byte/locale compatibility.
- `generate-regex-tests.mjs --check` regenerates all 417 native expectations in 27 public API groups for each backend. These are replays of the same programs, not additional coverage.
- `test-regex-host.mjs` compares 68 real CLI programs: 60 reused semantic/integration programs plus eight multi-byte RS matches crossing 64 KiB host reads. Stdout, exit status and stderr must agree.
- Historical `benchmark-regex.mjs` measured eight workloads, five also against fixed 0.7.0 commit `84b05a6`, with five serial processes per variant in rotating order. All outputs must agree; elapsed time includes startup and IO.
- Prior core/record/host/IO/CSV matrices remain active (1232 matches, three documented BOM differences). Adding 417 regex and 68 regex-host executions gives 1720 native requests with 1717 matches and three retained differences; the 68 host checks overlap the matrix in 60 places.
- Fixed reference details: script names containing underscores are rejected, LC has no extra fold table for U+0345, and unclosed quoted literals absorb the reference's wrapping parenthesis and are rejected. These choices are compatible with this pinned version and are not universal Unicode/RE2 claims.

Go sources consulted: [tables](https://github.com/golang/go/blob/go1.26.3/src/unicode/tables.go), [regex syntax parser](https://github.com/golang/go/blob/go1.26.3/src/regexp/syntax/parse.go), [simple folding](https://github.com/golang/go/blob/go1.26.3/src/unicode/letter.go). The parser/matcher are independently written MoonBit; only licensed Unicode data is translated.

The pre-final-fix performance sample is retained separately as `regex-performance-initial.json`; the final manifest uses `regex-performance.json` measured after the two parser fixes. Neither run is omitted based on its timing result.

## Unicode string conversion evidence

- `generate-string-unicode.py --check` verifies 328 upper/lower ranges from the unchanged Go 1.26.3 / Unicode 15.0.0 table, including alternating pairs and 2879 scalar values with a non-identity mapping. All mapped values are valid scalars with unchanged UTF-16 width. The BSD attribution and data SHA are retained.
- `test-string-scalars.mjs` runs one native program and the real current CLI over all 1112064 Unicode scalar values in order (surrogates excluded), emitting lowercase and uppercase for each. All 2224128 results are compared byte-for-byte. The original 8765167-byte native stream is saved as binary with version, executable hash, program and output digest. Golden replay checks the same request and bytes.
- `generate-string-scalar-tests.mjs` partitions that native output directly, without consulting production Unicode tables, into 543 independent API programs in 34 test groups. Both JS and Wasm-GC execute all scalars against native output. These chunks are not 543 additional native processes or new coverage.
- `test-string-reference.mjs` adds 58 native programs covering mixed text, ASCII/combining/astral/ligature/Turkish/Greek strings, unchanged originals, idempotence/composition, numeric/string types, CONVFMT, arrays/functions/fields, embedded controls, argument failures and regex/split integration. Exact successful output/status is required; designated invalid cases compare rejection. These generate four backend groups.
- `test-string-host.mjs` compares nine real CLI programs, including seven UTF-8 carry offsets near 64 KiB, 40000 records with field rebuilding, and a 999999-character record. Live output is compared byte-for-byte; saved reference checks use output length/SHA-256 and exact status/stderr.
- Prior 1720 native requests retain 1717 matches and three BOM differences. The new 58 contexts, nine host programs and one exhaustive scalar program give 1788 native executions, 1785 matches and three differences. Matrix programs, large scalar results and repeated backend checks are different units and must not be added as unique cases.
- `benchmark-string.mjs` records five serial fresh processes per variant for nine workloads, five against fixed 0.8.0 commit `ac96f1a`. Outputs agree with native GoAWK. Unicode workloads do not compare timing with the old incorrect conversion output. Timing includes startup/IO; final verification binds the measured compiled engine, production sources and benchmark/host scripts byte-for-byte. Documentation, module version and test-integration changes after timing are listed separately in the final manifest and do not overwrite original performance provenance.
- `verify.ps1` checks data/scalar/context regeneration, replays native vectors, tests both backends and runs real CLI scalar/stream checks alongside existing suites. All valid scalar conversions are covered; arbitrary invalid byte strings, default byte mode, locale rules, cross-platform execution and full production performance remain separate gaps.
